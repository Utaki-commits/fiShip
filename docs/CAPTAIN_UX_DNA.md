# 船長UX DNA — fiShip

## 最重要目的
海上・陸上どちらでも、落ち着いて安心して使える現場運営UI。

## ターゲットユーザー
- 30〜60代男性が中心
- ITに強いわけではない
- スマホは日常的に使える（X / Instagram / LINE 程度）
- 高密度な情報操作には慣れていない

## 主な利用タイミング
- 航海中・ポイント移動中・待機時間
- 出船前後・帰港後
- 陸上での確認・更新

## 通信環境の前提
海上では通信状況が不安定。
常時オンライン前提のUIにしてはいけない。

## UI優先順位
1. 出船状況の把握
2. 本日の予約確認
3. 乗船客確認
4. 保存状態の安心感
5. 簡単な更新

## 保存状態の表現ルール
- 保存中：ボタン上に「保存中...」を表示
- 保存成功：「保存しました」を2秒表示後に消える
- 通信失敗：「オフライン中 - 後で自動送信されます」を常時表示
- 未保存データあり：画面上部に黄色バナーで通知
- 同期待ち：「同期待ち件数」をバッジで表示

## 禁止
- SaaS管理画面風UI（高密度・多機能）
- 常時オンライン前提設計
- 通信失敗時に操作内容が消える設計
- 保存状態が分からないUI
- 一覧表示に10件以上を詰め込む
- 操作後に確認ダイアログを出さない破壊的操作
- 44px未満のタップ領域
- 片手操作できないタップ位置
