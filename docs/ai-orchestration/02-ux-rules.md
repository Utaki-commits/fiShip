# UX Rules

## 基本方針

- スマホファーストで作る。
- 中高年男性の船長が屋外でも読める大きさにする。
- 1画面で迷わせない。
- 操作は短く、確認は明確にする。
- 予約、連絡、承認、削除のような業務アクションを最優先する。

## 1画面1アクションルール

- 1画面の主目的は1つにする。
- 画面上の最重要CTAは1つだけにする。
- 例:
  - ログイン画面: ログインする。
  - 登録画面: 現在のステップを進める。
  - ダッシュボード: 今日・明日の予約を確認する。
  - 予約詳細/カード: TELする、承認する、連絡済みにする。
  - メモ予約画面: 解析する、確認後に登録する。
- 補助操作は見た目を弱める。

## タップ対象サイズ

- 通常ボタンの最小高さは `56px`。
- 主要CTAの推奨高さは `64px`。
- 入力欄の最小高さは `64px`。
- カレンダー月移動ボタンは `56px`。
- トグルは大きく、既存UIでは `72px x 40px` または近いサイズを使う。
- アイコンボタンだけ小さくする場合は、明示的に `minHeight: 'unset'` を指定する。

## 選択肢4つ以下ルール

- 主要な選択肢は4つ以下にする。
- 既存例:
  - 定員: `4名`, `6名`, `8名`, `10名`。
  - 便: `昼便`, `夜便`, `昼夜便`。
  - 休船対象: `全便`, `昼便のみ`, `夜便のみ`。
  - 休船種別: `メンテナンス`, `天候・波による中止`, `船のトラブル`, `その他`。
- 都道府県は先にエリアを選ばせ、直接47択を出さない。

## デフォルト値ルール

- 登録フォーム:
  - 定員は `4`。
  - 出船時刻は `05:00`。
  - 貸切OKは true。
  - 初心者歓迎は true。
  - 通知時間は `6:00〜21:00`。
- スケジュールフォーム:
  - 便は `昼便`。
  - 営業シーズンは1月から12月。
  - 曜日は日曜から土曜まで全選択。
  - 出発時刻は `06:00`。
- 予約メモ:
  - 人数未指定は `?` として扱い、AI解析結果を優先する。
  - 登録時の人数は最低1名。

## エラー表示ルール

- エラーは赤系背景で画面内に表示する。
- 既存カラー:
  - background: `var(--status-full-bg)`
  - border: `var(--status-full-bd)`
  - color: `var(--status-full-fg)`
- エラー文は具体的にする。
- 既存例:
  - `船の名前を入力してください`
  - `船長名を入力してください`
  - `出る曜日を1つ以上選んでください`
  - `出発時刻を入力してください`
  - `定員は1〜30名の範囲で入力してください`
  - `満員のため予約できません`
  - `過去の日付には予約を登録できません。`
- エラーはユーザーが次に何を直すか分かる文章にする。

## ローディング表示ルール

- 読み込み中は画面中央に `読み込み中...` を表示する。
- ボタン処理中はボタン文言を変える。
- 既存例:
  - `ログイン中...`
  - `送信中...`
  - `保存中...`
  - `登録中...`
  - `削除中...`
  - `AI解析中...`
- 処理中ボタンはdisabledにし、背景を `var(--border)`、文字を `var(--fg-3)` にする。

## 禁止事項

- 1画面に複数の主CTAを並べない。
- 小さい文字だけで重要な情報を出さない。
- 5つ以上の選択肢を同時に横並びにしない。
- 失敗時に無言で処理を止めない。
- `OCR`, `Webhook`, `API`, `DB`, `JSON` などのIT用語を船長向けUIに出さない。
- 予約を消す操作を確認なしで実行しない。
