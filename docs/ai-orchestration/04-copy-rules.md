# Copy Rules

## 文体

- 日本語のみ。
- 短く、具体的に書く。
- 船長が次に何をすればいいか分かる文にする。
- です/ます調を基本にする。
- 予約、承認、連絡、休船など業務語を優先する。

## 統一文言一覧

- 予約ステータス:
  - `承認済み`
  - `承認待ち`
  - `キャンセル`
  - `お断り`
- 空き状況:
  - `受付中`
  - `受付中止`
  - `満員`
  - `残りN名`
  - `昼便受付中`
  - `夜便受付中`
  - `昼便・夜便受付中`
- 休船:
  - `休船日`
  - `全便`
  - `昼便のみ`
  - `夜便のみ`
  - `メンテナンス`
  - `天候・波による中止`
  - `船のトラブル`
  - `その他`
- 連絡:
  - `TELする`
  - `未連絡`
  - `連絡済み`
  - `ご連絡をお願いいたします`
- 予約操作:
  - `承認する`
  - `お断り`
  - `取消`
  - `削除`
  - `編集`
  - `保存する`
  - `キャンセル`
- メモ予約:
  - `メモから予約を入れる`
  - `解析する`
  - `AI解析中...`
  - `この内容で予約を登録する`
  - `入力し直す`
  - `未送信のメモ`
- 予約完了:
  - `予約が完了しました`
  - `予約リクエストを送信しました`

## IT用語禁止リスト

- 船長向けUIに次の語をそのまま出さない。
  - `API`
  - `DB`
  - `JSON`
  - `Webhook`
  - `OCR`
  - `PDF`
  - `認証トークン`
  - `エンドポイント`
  - `レスポンス`
  - `ステータスコード`
  - `URL`
- 置き換え例:
  - `URL` -> `リンク`
  - `DB` -> `データ`
  - `エラー` は必要なら使ってよいが、何を直すかを書く。

## プレースホルダー規則

- 実在業務に近い例を書く。
- 既存例:
  - 船名: `例：海皇丸`
  - 船長名: `例：山田 太郎`
  - 港名: `例：糸島市志摩野北漁港`
  - アクセス: `例：野北漁港の白い灯台前に集合してください`
  - 駐車場: `例：漁港内無料駐車場あり`
  - 乗船料: `例：お一人様 15,000円（エサ・氷代込み）`
  - 便名: `例：タイラバ便、イカメタル便`
  - 魚種: `例：マダイ`
  - 予約メモ: `例：「土曜昼便2人 たなか 090-XXXX」`
  - 電話番号: `例：090-1234-5678 または +1-XXX-XXXX-XXXX`

## 必須バッジ規則

- 必須項目には `必須` バッジを付ける。
- 既存UIでは赤背景、白文字、小さめ、太字。
- 例:
  - `船の名前 必須`
  - `船長名 必須`
  - `都道府県 必須`
  - `お問い合わせ内容 必須`
- 必須バッジだけで判断させず、未入力時は具体的なエラー文を出す。

## ヘルプテキスト規則

- 何を入力するか、どこに表示されるかを書く。
- 既存例:
  - `予約フォームに表示されます`
  - `休船日は最優先で適用されます`
  - `空欄の場合は「昼便」として登録されます`
  - `複数日の場合は終了日も入力してください`
- ヘルプは本文より弱い色 `var(--fg-3)` を使う。
- ヘルプは1〜2行に収める。

## 禁止事項

- 船長に内部実装名を見せない。
- 英語のボタン文言を使わない。
- 説明文を長くしすぎない。
- `成功しました` だけで終わらせず、必要なら次の行動を書く。
- `失敗しました` だけで終わらせず、再試行か修正箇所を書く。
