# Review Checklist

## UXルール準拠チェック

- [ ] 画面の主目的が1つに絞られている。
- [ ] 主要CTAが1つに見える。
- [ ] 主要CTAは高さ64px前後。
- [ ] 通常ボタンは最低56px。
- [ ] 入力欄は最低64px。
- [ ] 選択肢は原則4つ以下。
- [ ] デフォルト値が設定されている。
- [ ] エラー文が具体的。
- [ ] 処理中にdisabledと処理中文言が出る。
- [ ] 中高年男性が屋外で読める文字サイズ。

## UIルール準拠チェック

- [ ] 色は `src/app/globals.css` のCSS変数を使っている。
- [ ] ライトモードで文字が読める。
- [ ] ダークモードで文字が読める。
- [ ] ヘッダー画像上の文字は白固定とtextShadowを使っている。
- [ ] カードはsurface背景、border、角丸。
- [ ] 予約カードは便、人数、ステータス、氏名、連絡状態、操作が分かる。
- [ ] 未連絡予約はpending色で強調されている。
- [ ] 編集は青アウトライン。
- [ ] 削除/取消/お断りは赤系。
- [ ] 承認は緑系。
- [ ] カレンダーの今日、選択日、過去日、満員、貸切が区別できる。

## コピールール準拠チェック

- [ ] UI文言は日本語。
- [ ] 船長向け画面にIT用語が出ていない。
- [ ] ステータス文言は統一されている。
- [ ] `満員`, `休船日`, `承認待ち`, `承認済み`, `お断り`, `キャンセル` を既存通り使っている。
- [ ] placeholderは実業務の例になっている。
- [ ] 必須項目に `必須` バッジがある。
- [ ] ヘルプテキストが短く具体的。

## 実装ルール準拠チェック

- [ ] 対象ファイルを読んでから実装している。
- [ ] 既存構造に沿っている。
- [ ] App Routerの配置が正しい。
- [ ] Supabase操作は `vessel_id` で絞っている。
- [ ] API Routeは適切なHTTPメソッドを使っている。
- [ ] API失敗時にJSON errorを返している。
- [ ] Client Componentで必要な場合だけ `'use client'` がある。
- [ ] 環境変数の実値を出していない。
- [ ] 未関係ファイルを変更していない。

## テストルール準拠チェック

- [ ] スマホ幅で確認した。
- [ ] 画面が白紙でない。
- [ ] Consoleに致命的エラーがない。
- [ ] 主要操作を1つ以上実行した。
- [ ] エラー表示を確認した。
- [ ] ライト/ダークで文字が読める。
- [ ] 予約ページのカレンダー表示を確認した。
- [ ] 予約カードの操作ボタンが押しやすい。

## デプロイ前最終確認

- [ ] `git status` で差分を確認した。
- [ ] 不要な差分がない。
- [ ] buildまたは該当検証が通った。
- [ ] `git add .` を実行した。
- [ ] `git commit` を実行した。
- [ ] `git push origin main` を実行した。
- [ ] GitHub mainにcommitがある。
- [ ] Vercelのデプロイが成功している。

## 禁止事項

- ローカルだけで反映済みと判断しない。
- 未検証のUIを本番反映済みとして報告しない。
- エラーや警告を隠して完了報告しない。
- 既存仕様と違う文言や色をレビューなしで増やさない。
- 予約、キャンセル、削除の業務ロジックを見た目だけで判断しない。
