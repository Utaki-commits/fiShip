# Auditor レポート — PR #28

**総合判定**: 🟡 Yellow — 人間確認推奨

## Architecture Auditor

**判定**: 🟡 YELLOW
**概要**: ハードコードカラー使用・CSS変数未使用が複数箇所あるが赤判定基準には抵触しない。軽微なUX懸念あり。

- [YELLOW] CSS変数（var(--ocean)等）を使わずハードコードした色（#6366F1, #D1D5DB, #F9FAFB, #E8EEF4など）を新規追加・変更している。UI Design Auditorルール上は赤だが、既存コードが全体的にハードコードカラーを使用しており一貫性の観点でyellowとして指摘。ただし #6366F1（night便タブ）は完全新規のハードコードカラーであり特に要確認。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] 選択不可カード（unavailableByConflict）から「選択できません」ボタンを非表示にした変更により、ユーザーが「なぜこの便を選べないのか」を理解する手段が『受付停止』バッジのみになった。元のメッセージ「同じ便種別で受付中の便があります」も削除されており、ITリテラシーの低い船長ユーザーが状況を把握できない可能性がある。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] カレンダーの選択不可セルから「×」表示を削除している。視覚的に選択不可であることを示すシグナルが減り、グレーアウトのみになるため、屋外スマートフォン使用ユーザーには分かりにくくなる懸念がある。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] borderLeft: '4px solid ...' が使われているが、UI Design Auditorルールでは border-width: 2px が禁止（0.5px原則）とある。4pxも同様に禁止対象に該当する可能性があるため要確認。ただし既存コードからの変更ではなく既存の記述であるため、本PRでの新規導入かどうか要確認。 (src/app/reserve/[vesselId]/page.tsx)

## UX Auditor

**判定**: 🟡 YELLOW
**概要**: ハードコードカラーの新規追加・CSS変数未使用が複数あるが、redルール違反は見当たらない

- [YELLOW] ハードコードカラー（#D1D5DB, #6366F1, #E8EEF4, #F9FAFB, #E5E7EB, #6B7280 など）を直接インラインスタイルに追加している。CSS変数（var(--ocean)等）を使わずハードコードした色の新規追加はUI Design Auditorの🟡ルールに抵触する（red条件との境界：既存カラー定義と近い色を独自定義）。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] ナイト便タブのアクティブ背景色に #6366F1（インディゴ系）を新たに導入しているが、既存パレットにない色であり、CSS変数化されていない。カード構造・ボタンスタイルの既存ルールとの整合性確認が必要。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] 「受付停止」バッジのfontSizeが10pxであり、重要情報ではないが情報表示として非常に小さい。14px未満のテキストは視認性が低く（屋外スマートフォン使用ユーザーへの影響）、確認推奨。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] unavailableByConflict時に予約ボタンを非表示にしたことで、「選択できません」という状態説明が削除され、「同じ便種別で受付中の便があります」の説明文も削除されている。ユーザーがなぜ予約できないかが不明になる可能性があり、エラー文が「次に何をすればよいか」を示さない懸念がある。 (src/app/reserve/[vesselId]/page.tsx)
