# Auditor レポート — PR #23

**日時**: 2026-05-23
**PR**: fix: カレンダーUI修正・設備リンク修正・テストデータ更新
**総合判定**: 🟡 Yellow — 人間確認推奨

## Architecture Auditor

**判定**: 🟡 YELLOW
**概要**: ハードコードカラーの継続使用・凡例簡略化による情報損失など複数のYellow指摘あり、Redなし

- [YELLOW] CSS変数（var(--ocean)等）を使わずハードコードした色（#F3F4F6, #9CA3AF, #1E4D3A, #1B2A4A, #1A2420, #CDD3DC 等）を新規追加・変更している。既存コードからの踏襲分もあるが、新規追加箇所でも同様にハードコードが継続されている。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] カレンダーセルの凡例が「○ 空き」「数字 残りわずか」「× 予約できません」の3種類から「○ 予約できます」の1種類に簡略化された。残りわずか状態・予約不可状態の視覚的区別と説明が削除されており、乗船客が空き状況を把握しにくくなる可能性がある。人間による確認が推奨される。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] 過去日・予約不可日のセルから「×」マークと「過去日」「予約できません」などのラベル表示が削除された。ITリテラシーの低いユーザー（30〜65歳の漁船船長）にとって、日付の色だけで予約可否を判断するのは不明瞭になる可能性があり、エラー文が抽象的で次に何を直すかがわからない状態に近い。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] 設備リンクが従来の幅100%ボタン（タップ対象56px相当）から「設備を見る →」というテキストリンク（aタグ、fontSize:12px）に変更された。タップ対象サイズが44px未満になる可能性があり、屋外スマートフォン使用の船長ユーザーには押しにくい。またフォントサイズ12pxは重要情報に近い箇所での使用として小さい。 (src/app/reserve/[vesselId]/page.tsx)

## UX Auditor

**判定**: 🟡 YELLOW
**概要**: カレンダーUIの簡略化によりユーザー向け情報（残席数・満席/過去日の区別）が失われ、設備リンクのタップ領域が縮小。UX品質に懸念あり。

- [YELLOW] 「残りわずか（残席数表示）」と「×（予約不可）」の表示が削除され、空きあり（○）のみの表示に簡略化された。船長が乗客に残席状況を正確に伝えられなくなるため、業務上の情報損失が懸念される。また過去日・満席・チャーター日の視覚的区別もなくなり、ユーザーが選べない理由を把握できない。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] 設備リンクが幅いっぱいのボタン（padding:14px）から小さな `<a>` タグ（fontSize:12px）に変更された。タップ領域が44px未満になる可能性が高く、屋外スマートフォン使用の対象ユーザーには操作しにくい。タップ高さ44px以上の確保が必要。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] 設備リンクの文言が「船の設備を見る」→「設備を見る →」に変更されている。既存の文言変更にあたり、Figma・仕様との整合確認が必要。 (src/app/reserve/[vesselId]/page.tsx)
- [YELLOW] cellBgやdateColorにハードコードカラー（#F3F4F6, #9CA3AF, #1B2A4A, #1A2420 など）が新たに追加されている。CSS変数（var(--ocean) 等）を使わずハードコードしており、デザイントークンルールからの逸脱が懸念される。 (src/app/reserve/[vesselId]/page.tsx)
