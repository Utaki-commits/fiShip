## dashboard

このUIの問題点を分析します：

## 問題点

1. **カラーの一貫性**
   - ヘッダーの濃紺と下部ナビゲーションバーの配色に統一感がない
   - ボタンやカード要素に視覚的な階層やアクセントカラーが不足

2. **文字サイズ**
   - 「今すぐ対応が必要な予約はありません」「本日出船なし」「明日出船なし」などの重要情報が小さく読みにくい
   - 海上での視認性を考慮すると、より大きなフォントサイズが必要

3. **タップ領域**
   - 右上のハンバーガーメニュー（三）のタップ領域が小さすぎる
   - 下部ナビゲーションのアイコン間隔が狭く、揺れる船上では誤タップのリスクが高い

4. **情報の優先順位**
   - 「出船なし」という否定情報ばかりで、次にすべきアクションが不明確
   - 空白スペースが多く、画面を有効活用できていない

5. **CAPTAIN_UX_DNA違反（海上での使いやすさ）**
   - 白背景は海上の強い日光下で反射して見づらい
   - 揺れる環境での操作を考慮した大きなタップ領域やコントラストが不足
   - 緊急性のある情報とそうでない情報の区別が不明瞭

## bookings

このUIの問題点を以下に挙げます：

## カラーの一貫性
- ヘッダーの濃紺とボトムナビゲーションの濃紺の色味が統一されているか確認が必要
- 選択状態の日付（26日）の枠線が細く、視認性が低い

## 文字サイズ
- カレンダーの日付数字が小さめで、揺れる船上では読みにくい可能性
- 曜日表示（日月火水木金土）が小さく、グレーで視認性が低い

## タップ領域
- カレンダーの各日付セルのタップ領域は適切に見える
- 「前月」「翌月」ボタンのタップ領域が小さく、船上での操作が困難

## 情報の優先順位
- 「この日の予約はありません」という情報が目立たず、重要な情報が伝わりにくい
- 予約がない日付と予約がある日付の視覚的な区別がない

## CAPTAIN_UX_DNA違反（海上での使いやすさ）
- 全体的にコントラストが低く、直射日光下では見づらい
- 月の切り替えが小さいボタンのみで、スワイプ操作に非対応の可能性
- 予約状況が一目で判別できず、業務効率が悪い

## bins

## UI問題点の分析

### 1. カラーの一貫性
- 「削除」ボタンのみ赤文字で他のボタン（編集・受付停止）と視覚的統一性がない
- 「有効」ステータスが黒文字で目立たず、重要情報としての視認性が低い

### 2. 文字サイズ
- 時間帯（06:00出港〜13:00）と定員情報の文字サイズが小さく、海上の揺れる環境下では読みづらい可能性
- 月の数字（1-12）が小さく、タップ対象としても視認対象としても不十分

### 3. タップ領域
- 上部の月選択ボタン（1-12の数字）が小さく、揺れる船上で正確にタップしにくい
- 「編集」「受付停止」「削除」ボタンが横並びで密接しており、誤タップのリスクが高い

### 4. 情報の優先順位
- 「定員 10名 / 8000」「定員 8名 / 9000」の意味が不明瞭（8000/9000が何を示すか説明不足）
- 現在の予約状況や空き状況が一目で判断できない

### 5. CAPTAIN_UX_DNA違反
- 重要なアクション（削除）に確認ダイアログの示唆がなく、誤操作時のリスクが高い
- 月選択の丸型インジケーターが小さく、手袋着用時や波で揺れる環境下での操作性が悪い

## blocked-dates

このUIの問題点を分析します：

## 問題点

1. **カラーの一貫性**
   - 「天候不順」ボタンのみ青色テキストで、他の選択肢（白背景ボタン）と視覚的統一感がない
   - 選択状態の深緑色は統一されているが、未選択状態のスタイルに一貫性が欠ける

2. **文字サイズ**
   - 日付入力フィールド（yyyy/mm,日）のプレースホルダーテキストが小さく、揺れる船上では視認性が低い
   - ボタン内テキストと見出しのサイズ階層が不明瞭

3. **タップ領域**
   - 「昼便のみ」「夜便のみ」ボタンが小さく、手袋着用時や揺れる環境でのタップが困難
   - 日付入力フィールドも縦幅が不足しており、正確なタップが難しい

4. **情報の優先順期**
   - 最重要な「期間」入力が上部にあるのは良いが、視覚的強調が弱い
   - 「理由メモ」の入力欄が大きすぎて、必須項目との優先度が不明確

5. **CAPTAIN_UX_DNA違反（海上での使いやすさ）**
   - 日付入力がテキスト形式で、揺れる船上でのキーボード入力は困難。カレンダーピッカーが必須
   - ボタン間の余白が狭く、誤タップのリスクが高い
   - 最下部の登録ボタンと底部ナビゲーションが近すぎて誤操作の危険性あり

## vessel

# 船長向け業務管理UIの問題点

## カラーの一貫性
- **問題なし** - 緑色のアクションボタンが一貫して使用されており、視覚的な統一感がある

## 文字サイズ
- ラベル文字が小さく読みにくい（特に「基本情報」「都道府県」などの見出し）
- 数値入力フィールド（営業時間「06:00」、裏地「8,000」など）の文字サイズが不統一

## タップ領域
- トグルスイッチ（電動リール用電源、エアコンなど）のタップ領域が小さく、船上での操作が困難
- 「無料」「有料」「空席コンバージョン」の3つボタンが狭い間隔で配置され、誤タップの危険性が高い
- 画像選択ボタン（ロゴ選択、バナー選択など）のタップ領域が不明瞭

## 情報の優先順位
- 重要な基本情報（船名、出港場所など）と設備情報（エアコン、ロッカーなど）が同列に扱われ、視覚的な差別化がない
- 予約ページQRコードが最下部に配置され、重要性が低く見える

## CAPTAIN_UX_DNA違反（海上での使いやすさ）
- 揺れる船上での細かいトグル操作は困難、より大きなスイッチUIが必要
- スクロール量が多く、片手操作や手袋着用時の操作性が考慮されていない
