## Architecture Auditor

**判定**: 🟡 YELLOW
**概要**: API Routeでのエラーハンドリング不足・Supabase操作の失敗時無視・ハードコードカラー使用が複数箇所で検出された。Redレベルの絶対禁止違反は確認されないが、複数のYellow問題がある。

- [YELLOW] customers/passenger_logsへのinsert・update・upsert操作でエラーを握りつぶしている（awaitしているがエラーチェックなし）。失敗しても処理が続行されレスポンスはok:trueを返すため、データ不整合が無言で発生しうる。 (src/app/api/board/[token]/route.ts)
- [YELLOW] bookingsテーブルのboard_completed更新（最終のupdate）でもエラーをチェックしておらず、失敗しても成功レスポンスが返る。 (src/app/api/board/[token]/route.ts)
- [YELLOW] CSS変数（var(--ocean)等）を使わずハードコードした色 `#7F1D1D` を新規追加している。UI Design Auditor ルール「CSS変数を使わずハードコードした色を新規追加している」に該当する。 (src/app/board/[token]/page.tsx)
- [YELLOW] ハードコードカラー `#fff`, `#f8f8f8`, `#e0e0e0`, `#555`, `#ccc`, `#222` が多数使われており、CSS変数を使っていない。 (src/app/board/[token]/page.tsx)
- [YELLOW] SMS APIルートにおいて、vessel_idによる認可・検証が一切行われておらず、board_tokenを知っている任意のリクエスト元がSMS送信を引き起こせる可能性がある（SMS送信コストの不正利用リスク）。 (src/app/api/sms/route.ts)
- [YELLOW] フォーム送信失敗時にalert()を使っている。船長向けUXルールでは「エラー文が抽象的で次に何を直すかわからない」に該当し、またalertはモバイル体験を損なう。 (src/app/board/[token]/page.tsx)
- [YELLOW] submitボタンが `submitting` フラグでdisabledになっているか確認できるが、diffが途中で切れており処理中文言の実装が確認できない。ローディング表示の有無を人間が確認すること。 (src/app/board/[token]/page.tsx)
