## Architecture Auditor

**判定**: 🟡 YELLOW
**概要**: facilities_override削除・空状態UI追加・セットアップ導線修正は概ね安全だが、いくつか確認推奨の点がある

- [YELLOW] setup/page.tsx でのSupabase bin_settings クエリに vessel_id による絞り込みはあるが、この vessel_id は直前に取得した data.id（自船のID）であることを確認する必要がある。コードフロー上は問題ないが、data が null の場合は return しているため安全。念のため確認推奨。 (src/app/dashboard/setup/page.tsx)
- [YELLOW] facilities_override を常に null で上書き送信している（`facilities_override: null`）。既存レコードに設備override情報が保存されている場合、PATCH時に全件 null で上書きされる破壊的変更となる。意図的な仕様変更かどうか確認が必要。 (src/app/dashboard/bins/page.tsx)
- [YELLOW] 空状態カード内のCTAボタン「＋ 便を追加する」と、bins.length > 0 時に表示される「便を追加する」ボタンの文言が微妙に異なる（「＋」の有無）。UI文言の統一が望ましい。 (src/app/dashboard/bins/page.tsx)
- [YELLOW] setup/page.tsx の notice 表示用 setNotice が使われているが、差分にNoticeのUI表示コンポーネントが含まれていない。notice が実際に画面に表示されるか確認が必要（未表示の場合、エラー文が抽象的・無言で止まるに相当する）。 (src/app/dashboard/setup/page.tsx)

## UX Auditor

**判定**: 🟡 YELLOW
**概要**: facilities_override削除・空状態表示追加・導線修正は概ね適切だが、UX上のいくつかの懸念点がある

- [YELLOW] 空状態カード内のサブテキストのフォントサイズが15px、カラーが '#5A6A78' とCSS変数を使わずハードコードされている。UI_GUARDRAILSではCSS変数使用が原則。 (src/app/dashboard/bins/page.tsx)
- [YELLOW] 空状態の説明文字（fontSize: '15px', color: '#5A6A78'）はCSS変数（var(--ocean)等）を使わずハードコードされた色が新規追加されている。既存のcolors.*オブジェクト経由でもなく独自の色値が混在している。 (src/app/dashboard/bins/page.tsx)
- [YELLOW] setup/page.tsx の useEffect 内で supabase.from('bin_settings').select() を直接呼んでいるが、vessel_id による絞り込みは data.id で行われており問題は低い。ただし、getSession() 前にウィンドウ検索パラメータ処理を移動した結果、step設定とloading完了のタイミングが変わっており、ローディング中にstepが未設定のまま描画される可能性がある。UX上チラつきや誤表示のリスクがある。 (src/app/dashboard/setup/page.tsx)
- [YELLOW] setNotice('便を1件以上保存すると次に進めます。') というガイダンス文言が追加されているが、この通知がUI上どのように表示されるか（フォントサイズ・視認性・位置）がdiffから確認できない。船長向けUIとして14px以上・十分な視認性が確保されているか確認が必要。 (src/app/dashboard/setup/page.tsx)
- [YELLOW] facilities_override を常に null で送信するよう変更しているが、既存レコードに保存済みの facilities_override データが上書き削除される破壊的変更となる。意図的な削除であれば問題ないが、既存データへの影響について確認が推奨される。 (src/app/dashboard/bins/page.tsx)
