# Auditor レポート — PR #16

**日時**: 2026-05-21
**PR**: feat: 予約確定時のSMS送信トリガーを追加
**総合判定**: 🟡 Yellow — 人間確認推奨

## Architecture Auditor

**判定**: 🟡 YELLOW
**概要**: SMS送信トリガー条件の変更とboard_token自動生成に軽微な懸念あり

- [YELLOW] SMS送信トリガー条件が `previousBooking?.status !== 'confirmed'` から `previousBooking?.status === 'pending'` に変更されています。以前は 'rejected' や他のステータスから 'confirmed' に遷移した場合もSMSが送信されていましたが、この変更により 'pending' 以外のステータス（例: 'rejected' → 're-confirm'）からの遷移時はSMSが送信されなくなります。業務フロー上、意図した変更かどうか人間による確認が必要です。 (src/app/api/bookings/route.ts)
- [YELLOW] `board_token` がリクエストに含まれない場合にサーバー側で自動的に `randomUUID()` を割り当てる処理が追加されました。board_tokenの生成責任・ライフサイクル・乗船QRなどとの連携仕様が既存設計と整合しているか確認が必要です。意図しないトークンが発行されることで、後続の乗船確認フローに影響が出る可能性があります。 (src/app/api/bookings/route.ts)

## UX Auditor

**判定**: 🟡 YELLOW
**概要**: ロジック変更2点にリスクあり：board_token自動生成の意図不明・SMS送信条件の絞り込みが未確認

- [YELLOW] board_tokenが未指定の場合にrandomUUID()で自動生成するよう変更されているが、board_tokenが発番される業務的タイミング・用途（乗船QRコード等）と整合しているか確認が必要。意図せず全予約にトークンが付与されると、未確認のまま乗船許可が発行されるリスクがある。 (src/app/api/bookings/route.ts)
- [YELLOW] SMS送信条件を `previousBooking?.status !== 'confirmed'` から `previousBooking?.status === 'pending'` に変更したことで、`rejected` や `cancelled` などpending以外のステータスから `confirmed` に遷移した場合にSMSが送信されなくなる。これらのケースが業務上発生しないか、または意図的な除外かを確認する必要がある。 (src/app/api/bookings/route.ts)
