# Concept UI

## Purpose

- Store v0 or other concept UI output before implementation.
- Preserve why a concept was accepted or rejected.

## Required Entry Format

```md
# YYYY-MM-DD Concept Name

## Tool

- v0 or other generator.

## Target Screen

- Route or feature name.

## Prompt

- Prompt used to generate the concept.

## Accepted Ideas

- ...

## Rejected Ideas

- ...

## Implementation Notes

- How Codex should adapt this to existing tokens and components.
```

## Prohibited

- Do not commit generated UI as production-ready without review.
- Do not use shadcn/ui or Tailwind output directly unless the implementation rules are updated.
