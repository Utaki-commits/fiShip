# UI Guardrails — fiShip

## 最重要原則
乗船客UIと船長UIを同じ思想で作ってはいけない。
この2つは根本的に異なるUX思想で設計すること。

| | 乗船客UI | 船長UI |
|---|---|---|
| 最優先 | 空席視認速度 | 安心・安定した運営 |
| 環境 | 陸上・Wi-Fi | 海上・通信不安定 |
| 目的 | 空いているか確認して予約 | 現場で安心して運営 |
| 設計思想 | 空席視認UI | 現場運営UI |

## 乗船客UI 絶対禁止
- 乗船客UIをSaaS管理画面のように設計しない
- 空席視認性より絞り込みを優先しない
- 予約CTAを長いスクロールの下に置かない
- 管理画面風テーブルUIを使わない
- 複数カラムレイアウトを使わない

## 船長UI 絶対禁止
- 常時オンライン前提のUIにしない
- 通信失敗時に操作内容が消える設計にしない
- 保存状態が分からないUIにしない
- SaaS高密度管理画面にしない
- 破壊的操作に確認ダイアログを出さない設計にしない
- 44px未満のタップ領域を作らない

## 共通禁止
- IT用語をUIテキストに使う
- 1画面に主要アクションを2つ以上置く
- 情報を詰め込みすぎる
- 状態・ステータスをテキストのみで表現しない
  （必ずバッジ・アイコンで視覚的に表現する）
